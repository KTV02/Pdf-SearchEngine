# Migrating an existing installation

Back up the complete existing installation, configuration, index data, PDFs, email state, cloud state, and Docker volumes before changing it. Keep that backup private. Do not replace or restart a working server until a separate test installation has passed.

1. Record the current effective Compose configuration and running image versions without sharing its output; it may contain credentials. Keep the existing `.env`, `docker-compose.override.yml`, `roles.json`, and `access_config.json` private.
2. Start from a clean copy of the shared source. Copy local values into its ignored `app/.env` and root `compose.override.yaml`. Point storage variables at the existing host directories. The defaults now use `app/data/`; they do not automatically pick up old paths. Carry over any custom network, capability, token mount, and image overrides explicitly.
3. Copy the existing role and access JSON files into the private directory selected by `CONFIG_HOST_PATH`, or configure `ROLE_CONFIG_PATH` and `ACCESS_CONFIG_PATH` to point to the existing container paths and mount them in your local override. Preserve ownership and permissions. If the old application used hard-coded non-admin role-to-index mappings, save equivalent mappings as `role_indices.json` under the private config directory; otherwise those legacy roles will have no index access. Admins use the current list of indexes automatically.
4. For a multi-user or proxied installation set `LOCAL_SINGLE_USER_MODE=false`, retain the actual allowed frontend origins and administrator identities, and ensure the proxy is trusted and strips client-supplied identity headers. Preserve the coordinator token mount and the network route to the coordinator, if used. Remove any `TEST_BYPASS_TOKEN` from the installation's settings: the installation stack ignores it, and integration tests run only in the isolated stack started by `scripts/run_integration_tests.sh`. Set `MAIL_TOKEN` to a private random value rather than the public default.
5. In a separate environment with copies of the data, build and test startup, permissions, searches, uploads, mail, cloud connections, and backups. Check the merged configuration with `docker compose config` but do not publish its output. Only then schedule a switch on the real host with a tested rollback.

Git ignore rules apply only to files that are not already tracked. A previously tracked secret stays in Git history even after deletion. Never make an old repository public merely because its latest files have been cleaned; inspect its entire reachable history and rotate any exposed credentials. A new public repository initialized from a reviewed snapshot avoids publishing the old commit history. Keep private history and backups access-controlled.
