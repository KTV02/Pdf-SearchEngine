# Migrating an existing installation

Back up the complete existing installation, configuration, index data, PDFs, email state, cloud state, and Docker volumes before changing it. Keep that backup private. Do not replace or restart a working server until a separate test installation has passed.

1. Record the current effective Compose configuration and running image versions without sharing its output; it may contain credentials. Keep the existing `.env`, `docker-compose.override.yml`, `roles.json`, and `access_config.json` private.
2. Start from a clean copy of the shared source. Copy local values into its ignored `app/.env` and root `compose.override.yaml`. Point storage variables at the existing host directories. The defaults now use `app/data/`; they do not automatically pick up old paths. Carry over any custom network, capability, token mount, and image overrides explicitly.
3. Copy `access_config.json` to the private directory selected by `CONFIG_HOST_PATH` or mount its containing directory and set `ACCESS_CONFIG_PATH`. Keep `roles.json` and `role_indices.json` in the private backup for reference. Convert every legacy IP grant into an explicit entry for the person's Tailscale login. In the Admin interface, grant the corresponding index read and write permissions and grant admin only to the intended administrators. Existing valid login grants carry over. In a hand-edited file, use unique logins, JSON booleans for `admin`, and arrays of names for `read` and `write`. Correct malformed access settings on disk if the API reports that they are unavailable.
4. For shared access, set `LOCAL_SINGLE_USER_MODE=false`, configure `ADMIN_TAILSCALE_USERS`, and retain the exact allowed frontend origins. Send browser traffic through Tailscale Serve and keep the direct ports private. If Serve connects from a peer other than loopback or the Docker gateway, set `PDFSEARCH_TRUSTED_PROXY_IP` to that exact peer. Point cloud callback URLs to the API through Serve. Reconnect cloud accounts that need to move from an old IP owner to a registered login and select the new connection in the relevant index settings.
5. Preserve any coordinator token mount and network route. Set `MAIL_TOKEN` to a private random value in both services before restoring mail jobs. The monitor retries a rejected attachment before advancing its mailbox checkpoint. Scripts that used IP grants need an authenticated user path. The mail credential authorizes attachment uploads only. Remove any installation `TEST_BYPASS_TOKEN`. Use `scripts/run_integration_tests.sh` for the isolated test stack.
6. In a separate environment with copies of the data, verify startup, permissions, searches, uploads, mail, cloud returns, and backups. Check the merged configuration privately with `docker compose config`. Schedule the host switch after testing the rollback.

Git ignore rules apply only to files that are not already tracked. A previously tracked secret stays in Git history even after deletion. Never make an old repository public merely because its latest files have been cleaned; inspect its entire reachable history and rotate any exposed credentials. A new public repository initialized from a reviewed snapshot avoids publishing the old commit history. Keep private history and backups access-controlled.
